# Hair Tool guides to Chaos Cloth

Explicit Export scopes can be saved in `scene['send2ue_export_unit_names']` as a
JSON list of Empty names. They survive file reload. The same WindowManager key
overrides this only for the current operation; an explicit `[]` selects shared
rig/dependencies without any Empty unit. Files without either key keep the
existing all-units behavior. Each unit's saved `send2ue_export_source_names`
still declares its final render sources; the physical generating input is
captured separately rather than admitted as an ordinary render source.

Enable **Hair guides to Chaos Cloth** in Send to Unreal's Export settings. Choose
an existing cloth physics template and body skeletal mesh. A physics asset is
optional: leave it blank when external body collision is unnecessary. The import
then clears inherited external collision. A nonempty path keeps the chosen asset. The
normal Export collection, naming, material handoff and FBX importer remain in use.
The hair meshes must use the body's existing Skeleton import setting.

The ordinary skeletal importer has a separate **Automatic Physics Asset** switch
under Paths. Its default preserves legacy reuse/creation of `<mesh>_PhysicsAsset`.
Disable it to skip both implicit assignment and creation. An explicit asset path
is still used when supplied, and a missing explicit asset is reported rather than
silently creating a different physics asset.

Each final Hair Tool output is paired with its actual immediate **Source Surface**
generator input. A two-stage system uses its first source; a three-stage system
uses its intermediate source. Hierarchy depth and object naming do not choose the
simulation mesh. A disposable guide copy stamps source mesh island ownership
before the disposable render generator is evaluated. Hair Tool's grid generator
uses its native `src_island_index` when it does not propagate the custom stamp.
Every connected output strand must retain one generating source island.

An evaluated guide with any positive own `ChaosWeight` is exported separately as
`<asset>_GuideSim`, including all its vertices and islands. Zero-weight roots and
zero-weight islands within that active source are preserved. No authoring profile
edits or paint generation occur. The simulation FBX G channel
comes from that guide's own `ChaosWeight`, never the render mesh's colors.

**Simulation guide shape** defaults to **Optimized ribbon guides**. Supported
Hair Tool `Circle_Profile_UV` and `Flat_Profile_UV` generators use the same
optimization and validation path, exporting an open two-point profile while
retaining their existing spline evaluation, longitudinal samples, width fields,
and own paint. Only disposable simulation copies use this profile. The render
generator still evaluates the original guide shape. **Original guide** restores
the original simulation topology. Flat guides (including the intermediate
simulation ribbon feeding **Strands from Grid Surface**) use their native flat
profile at **Profile Res = 1** on the disposable simulation copy. An already
one-segment flat guide retains its rail positions. Higher transverse resolution
is reduced while the render generator keeps the authored profile resolution.
Unsupported node layouts or failed conversion checks retain the original guide
and record a fallback reason in `sources[].simulation_mesh` and each part.

An optional integer `send2ue_cloth_ribbon_profile_points` on the simulation
source accepts `2` (default) or `3`. Three points add a center support to the
disposable open profile without changing the rails, spline samples, source
weights, or render generator. Receipts record the selected count; invalid values
retain the original geometry with a diagnostic. This is a topology option,
not proof that Unreal proxy binding or motion has passed. Artist-painted
two-rail arclength transfers retain their existing compatibility checks.

The render source may opt into `send2ue_cloth_clean_degenerate_render=true`.
Only the disposable evaluated render is triangulated; exact zero-area triangles
and their newly orphaned vertices are removed. An explicit positive
`send2ue_cloth_cleanup_position_scale` additionally removes triangles whose
corners coincide at the target float32 position precision (100 for the verified
meter-to-centimeter handoff). Without that declaration only exact-zero cleanup
is allowed. The conversion verifies retained positions, all point/corner/face
attributes, UVs, material assignment and shading, and preserves the artist
objects. It rejects custom split normals because BMesh would re-encode them.
Receipts distinguish exact-zero faces from target-collapsed faces and record
the latter's original area; this is not a general small-triangle threshold.

Ownership is per generating **spline**, not per parent object. If one parent
contains splines A, B, and C, the children generated by A may bind only to A's
ribbon, including when B or C crosses it. The exporter proves a bijection between
native mesh islands and stamped spline IDs, preserves each spline's sample IDs,
and verifies that every connected child strand carries one source island. It
does not infer ownership from distance. Unresolved ownership still defers cloth
generation. Conversion receipts include the native-island-to-spline crosswalk,
sample/guide counts, geometry counts, center and weight errors, and recipe version.

Hair Tool's Prism generator filters source islands in `Pre-Split Edges` and then
rewrites `src_island_index` using the remaining mesh islands. Those compact IDs
are not original spline IDs. Ribbon export therefore compares the carried
original FACE island stamp with an independent CURVE spline stamp on every render
vertex. The verified crosswalk is recorded under `render_ownership`; a mismatch
defers cloth generation. Tests include three splines with the first filtered out,
crossing children closer to a foreign guide, and an intentionally corrupted stamp.

Unreal may split a single source render vertex into several normal/tangent
corners. Native binding shares their position support only when the original
source identity is unique, the individual spline ID and fixed blend match, and
position and skin weights agree. Each corner retains its own normal/tangent
endpoints. Ambiguous coincident strands are not merged. The binding receipt
includes rigid/smooth deformation probes and the shared-source corner gap.

If the entire evaluated source has zero weights, or the attribute is absent, its
complete ordinary render output is retained with no simulation geometry. The
manifest records `status=guide_weights_all_zero`, the actual resolved guide and
search receipt, and `excluded_sim_vertices`. An absent attribute remains distinct
from authored zero through `authored_weight_present=false`. This whole-source
decision happens before byte-color quantization; even a tiny positive authored
weight keeps the entire source. Render colors follow the existing material packing.
Both outputs follow the existing Hair Tool exporter rule of full head-bone binding
to the same complete armature; this feature does not add a skin transfer rule.
The final cloth uses the chosen body's reference skeleton after checking bone
names and parents. This keeps the imported bone indices and weights while avoiding
FBX reference-scale differences when the cloth follows that body in Unreal.

When no guide exists after generator-input, Hair Tool registry and hierarchy
searches, that output remains ordinary skinned render geometry with **no
simulation**. Render-as-simulation fallback is removed. The version 2 packet
records `guide_ids=-1`, exact `render_only_vertex_indices`, and the completed
search receipts in `render_only_sources`. Mixed exports keep the full render
mesh while their simulation FBX contains only actual guides. Native binding
keeps unguided vertices fully skinned with zero effective simulation influence;
it never assigns them to a nearby guide. With no guides anywhere in an export,
`simulation_enabled=false`: no simulation FBX or Cloth build is made, and the
receipt reports `render_only` with no current cloth asset path. The same path is
used when every resolved guide is wholly zero-weight or unpainted. Mixed packages
keep the complete render mesh and bind those static outputs to skinning only,
with no proxy influence from nearby active guides. Previously
generated assets are retained; this exporter does not assign actor components.
An unresolved or unsupported existing guide is not classified as absent.
Optional cloth generation is deferred with a diagnostic while ordinary Send to
Unreal export continues. Old render-as-simulation packets need re-export; they
cannot recreate the removed fallback.

The `.hair_guide_cloth.json` sidecar contains world-space positions in meters,
actual exported triangles, per-vertex generating guide IDs, simulation byte G,
unquantized source paint, render RGBA/UV data, source search receipts, bone rest
matrices and a content hash. The final exported member carries a portable
`_hair_guide_cloth_record`; ordinary or deferred post-import executes
`resources/pipeline/ue_hair_guide_cloth.py:apply_hair_guide_cloth(record)` after all
required FBXs have been imported (render only when simulation is disabled).
Changed geometry, paint, ownership, render payload or
armature state changes the packet hash and requires a new binding bake.

Only the cloth command receives a scoped 900-second response timeout. Existing
global RPC preferences and all normal import settings are preserved. Cloth
failures preserve already imported meshes and the previous Cloth, but fail the
requested Send2UE operation. Recovery never converts a failure into success.
The native failure receipt includes the original exception type, message and
traceback under `SEND2UE_HAIR_GUIDE_CLOTH_ERROR`; the Blender extension rejects
that receipt, reports an error and prevents coordinated completion. A failed
Cloth update can leave a newer imported mesh paired with the previous Cloth;
it must remain incomplete until the reported problem is resolved.

Cloth duplication does not deep-copy an externally referenced Dataflow in UE5.8.
Before editing a build source, publication stage, new final, or existing final,
the pipeline retains an already-owned embedded graph or duplicates the external
graph into a unique destination dependency. It verifies node identities, GUIDs,
activation, properties, links, variables and the Cloth's terminal/override/owner
context before editing. Existing final configuration and paint chains remain the
starting point. The graph dependency is saved before its Cloth, including after
graph edits. Unsaved external template/output graphs stop the optional build.
Context inspection uses native struct ExportText and the null-safe Agent
ListVariables API. Only the leading generated transient PropertyBag type token
is normalized when SyncVariables recreates its schema object; payload text,
artist paths, override GUIDs and graph variable schema/values remain checked.

Failed requests remove only their exact new assets. A failed rollback or deletion
retains dependencies through every caller, rather than force-deleting something
a surviving Cloth may reference. Once final publication is saved, receipt or
staging cleanup errors cannot remove its dependencies; staging cleanup failures
are reported separately as `staging_cleanup_warning`. External graphs remain
supported. Existing template LOD0 behavior is unchanged.

Validation includes `tests/test_hair_guide_cloth.py`,
`tests/test_ue_hair_guide_cloth.py`,
`tests/test_ue_hair_guide_cloth_external.py` (shared external references, separate
graph/Cloth disk state, repeat publication and injected recovery failures),
`tests/test_ue_hair_source_corner_identity.py`, and the real Hair Tool node-library
fixture in `tests/blender_hair_guide_ribbon_smoke.py`. Blender registration tests
must use `default_set=False` and never save preferences from factory startup.

After a verified package reload, ordinary export refreshes existing cloth
components in the current editor world whose asset is the exact output or has
the matching generated owner metadata. It explicitly resets configuration and
recreates the simulation proxy, including repeated imports of the same asset
object. Existing simulation enabled/suspended flags, leader and transform remain
unchanged; the receipt lists refreshed components under `live_components`.

A wholly render-only export hides and suspends that previous generated cloth.
It shows an existing source renderer only when asset, leader, parent and relative
transform all match; otherwise it creates an ownership-tagged render component
on the same actor. Returning to simulation restores prior visibility and flags,
removing only that tagged helper. Restoration data lives in component tags so
Python reload does not lose it. This does not spawn actors or save the level.
The stateful propagation tests are in `tests/test_ue_hair_live_refresh.py`.

## Runtime response checkpoint (2026-09-09)

The Shibuki integration is saved in MyProject2 Perforce changelist **625** before
further motion refinement. It contains the four guide/render packages, exact
per-spline bindings, original skinned collision, the test-level instance settings,
and `Docs/Cinematics/Shibuki/HAIR_RESPONSE_BASELINE_20260908.json` for restoration.

This exporter supplies geometry, ownership and each guide's own G. The project's
native Chaos Cloth wind bridge supplies the additional hair response; this is not
a new built-in Chaos turbulence setting or an exporter-authored animation. Its
opt-in gust acceleration preserves gravity and temporarily replaces surface
Drag/Lift. The recorded profile uses time scale 3, stretch resistance scale 10,
coupling 0.35/s, stream/transverse/vertical variation 0.35/0.60/0.25, and a wind-only
acceleration cap of 200 cm/s². Stretch scaling preserves the existing maps and
bending properties. Disabling the mode restores owned original values. Only the
four explicitly selected hair components use it; clothing is excluded.

The accepted baseline retains the original ribbon width, authored resolution,
skin collision and parent-spline ownership. A separate half-width trial did not
produce the missing side-hair swish and was reverted; no extra width-scale option
is shipped here. Render G was not found to drive the active cloth path.

Applying the shared gust profile to all four parts improved the response but made
coherent clump motion more apparent, especially in the back hair. This checkpoint
does not claim final motion quality. The next refinement should introduce only
small differences in guide response while keeping the common wind flow. It must
retain each child's generating parent and must not animate simulation vertices
directly or assign large unrelated phase offsets to individual clumps.

## Reimporting configured cloth and explicitly skinned cards

Reimport preserves the existing downstream solver and collider graph. Simulation
WeightMap nodes are also supported when their data can be carried forward without
guessing: unchanged topology keeps authored values, a verified binary kinematic
mask follows the rebuilt kinematic selection, and `CodexParentForceKey` is rebuilt
from stable source-guide/spline identities. Arbitrary paint on changed topology,
active paint snapshots, and invalid provenance still stop publication. Failed
publication restores the previous import, map values and metadata.

For Hair Tool cards with **Transfer Weights** enabled, the configured Transfer
Source is evaluated through the installed Vertex Data Tools operator before the
FBX export mesh is bound. It must supply valid deform weights and its expected
Armature modifier. Such assets do not require a head bone. Ordinary hair keeps
the existing rigid head-binding behavior. This supports tail rigs through normal
Send to Unreal without a separate exporter.

The generated `<asset>_GuideSim` also copies the resolved render's Transfer Weights
settings and uses that same native binding operator and source mesh. Its manifest
records the transfer source instead of performing a head-bone lookup. This lets
the simulated guides follow an animated tail's existing bones. Head-bound hair
retains its original rule. `tests/blender_hair_guide_skin_smoke.py` checks native
render/GuideSim weight equality on a twelve-bone rig without Head and the unchanged
rigid Head case; it never saves scene files or preferences.

After changing an installed add-on junction, reload extensions in every running
Blender that will export. A previously loaded extension can retain its former
absolute pipeline path even when the junction and Git checkout have changed.
Preserve scene settings across Reload Extensions and verify the live material
and cloth pipeline paths before sending.
## Stable guide identity across artist renames

Generating guide objects may pin their original identity token in the custom
property `send2ue_guide_identity`. Native capture reads this value without
changing the authoring scene and records it as `parts[].source_identity`; the
current display name remains in `source_guide`. Parent-spline keys use the
pinned token, so later display-name normalization does not invalidate artist
maps. Legacy packets without the field retain their existing name-based keys.
Duplicate tokens on different guides and empty or malformed tokens are rejected.

Initialize a token in the source authoring workflow before later renames. When
migrating existing painted cloth, use the verified historical rename record and
check its old parent keys; do not guess a token from spatial proximity. A token
does not alone authorize geometry resampling. New exports declare the
`source_ribbon_paint_transfer` v1 `stable_parent_arclength` contract. Only proven
two-rail FLAT/CIRCLE ribbon conversions may use it: the receiver matches stable
parent-spline keys, checks complete strip topology and source vertex identities,
requires unchanged root and tip centers and consistent rail orientation, then
interpolates each rail's paint along normalized centerline distance. There is no
nearest-guide search or averaging between rails. Unsupported or ambiguous
correspondence still fails before publishing the cloth. This also avoids stale
manual allow-lists after a verified generator's sample count changes. Legacy
explicit `rooted_ribbon_arclength` policies remain supported.

Temporary project exports use `blender/send2ue-session-data/<process-id>` under
the system temporary directory. Unregistering one Blender cleans only its own
process folder. The new folder is outside the legacy shared `send2ue/data`
directory so an older running Blender's cleanup cannot erase an active FBX or
paint manifest. Explicit user-selected disk export folders are unchanged.

## Native three-stage Hair Tool chains

An explicit Hair Tool source identifies its native pipeline. The export selector
follows actual Hair System Setup source links within the same Empty unit to the
final Hair Tool output before upstream suppression. For surface -> profiled spline
mesh -> generated hair, the generated hair is the render output and its immediate
profiled spline mesh is the simulation source. RIBBON mode converts that second
stage on disposable export copies; it does not simulate the initial base surface.
For this native three-stage contract, the capture path always requests RIBBON,
including when an older saved setup helper still writes ORIGINAL. Ordinary
two-stage surface-to-hair sources retain their existing mode setting. Live preview
verified the three-stage result without changing the old saved ORIGINAL setting.
Native Random Float Sampler -> SamplerToAttribute response maps are preserved on
reimport when they create a new SimVertices3D float attribute and its name output
feeds a real native weighted physics input. The sampler and attribute must belong
to that validated branch. Render/color writes, replacement of MaxDistance or an
existing authored map, foreign connections and unused branches remain rejected.
The new ten branch-validation tests and existing eighty-nine publication tests
pass; actual native sampler evaluation/reimport is a separate pending live check.
No object-name suffix or fixed parenting depth determines the stage. Already-final
sources remain unchanged; ordinary explicitly selected meshes do not admit legacy
children. Cycles are rejected. The eight stage-selection regressions are in
`tests/test_hair_pipeline_stage_selection.py`; actual current Long/Short Blender
preview verified ten/six independent ribbon guides with unchanged source geometry
and G, and unchanged final render geometry. Actual Unreal transfer remains a
separate verification step.


## Native G and authored Dataflow dependencies

The source graph reads simulation-mesh G through
`FCodexClothVertexColorWeightMapNode` and connects its map-name output to the
original MaxDistance config. Standard GetVariable/Selection inputs, their native
types, variable bag and instance context remain graph dependencies. Existing
final physics is preserved; a fresh stage retains the source G/MaxDistance and
kinematic-map path without applying the entire physics chain twice.

WeightMap nodes may use a registered String GetVariable output on
`InputName.StringValue` with an empty OutputName. The pipeline validates the
native getter, graph variable and available instance overrides without baking
that String into a field. Ambiguous, unsupported or conflicting identities stop
the update. Existing literal map names remain supported.

`ue_hair_weight_routes.py` plans and verifies native G, kinematic masks and
skinning blend dependencies. `ue_hair_collection_proof.py` compares complete
native managed-attribute values, including UVs. Complete equal semantic proofs
may normalize serialization/name-enumeration order; unsupported attributes fail
closed, and older native output keeps its strict comparison. Publication retains
the existing explicit physics-config/new-map allowances and checks all other
attribute schemas and values.

These paths require the project's native CodexClothTools nodes and audit APIs.
The app-free tests cover graph contracts, preservation and failure paths; they do
not establish successful native migration or an FBX reimport of a production
asset. Existing binding-only assets inherit G from their validated BindingData through `GeneratorBindings`; they do not need a duplicate G node in the final graph. Reimport preserves that graph and applies the same complete collection proof. An existing explicit native G route still receives its guarded source rebinding; reimport never implicitly migrates artist graphs.

## Coordinated import settling

Initial Unreal discovery keeps its short timeout. After a coordinated request has
successfully imported an asset, follow-up discovery can wait up to the configured
RPC response timeout while Unreal rebuilds dependent Cloth assets. Only discovery
and a harmless readiness probe are retried; dispatched import commands are never
replayed automatically.

For an existing binding-only graph, the temporary publication check now imports
the verified BindingData directly, matching the final graph. It does not apply G,
MaxDistance and kinematic selection a second time. This removes redundant
MaxDistance property warnings without disabling warnings or relaxing the complete
collection proof. Existing explicit native G routes and first publication keep
their native route validation.

A parked native simulation config is preserved when it has exactly one Collection
input from the live chain and no connected outputs. It does not contribute to any
terminal. Disconnected subgraphs, paint/geometry branches and parameter consumers
continue to fail validation. Artists can keep such a config for later use without
temporarily deleting it for reimport.
